## Addendum — frontend deep audit (2026-10-14, ~17:20 EDT)

Full page-by-page + connection verification of all 30 routes and 59 frontend
API calls. Good news first: **every route resolves, every nav link works, and
all 59 REST endpoints the frontend calls exist in the backend.** No missing
REST connections. The gaps:

### 🔴 1. WebSocket event mismatch — live trade toasts are dead
`frontend/src/services/socket.ts` listens for `trade:executed` (payload
`{ trade, mode }`). The backend never emits it — it emits **`trade:update`**
(`backend/src/services/alpacaMarketStream.ts:234`) with a raw Alpaca
`tradeUpdate` object (different shape). Fix: align on one event name + payload
in both files. Also dead listeners (`council:start`, `agent:status`,
`council:complete`, `position:closed`, `guardrail:triggered`) and backend
emits nobody consumes (`quote:update`, `polymarket:scanning`, …) — harmless
but should be pruned.

### 🔴 2. Fabricated data presented as real on 4 pages
- `Screener.tsx` — 100% hardcoded mock data: stale prices (BTC-USD at
  $67,420) and `Math.random()`-generated RSI/MACD/volume/earnings (lines 19–37).
  Calls no API.
- `CryptoStrategy.tsx` — backtest stats, signals, equity curve driven by
  `Math.random()` (lines 93–130, 375–390).
- `MarketRecap.tsx:167` — random `change1d` fallback.
- `InsiderTransactions.tsx:146,176` — random `shares`/dates.

These pages look functional but show invented numbers — the single biggest
credibility risk before any public launch. Fix: wire real endpoints or label
them "Demo data" explicitly.

## Addendum — backend deep audit (2026-10-14, ~17:25 EDT)

### 🔴 1. README Step 6 was wrong (caught by audit, fixed same day)
The account-setup curl used `POST /api/auth/setup` — that route **does not
exist** (404). The real route is `POST /api/auth/setup-owner`
(`backend/src/routes/index.ts:116`), takes only `{email, password}` in the
body (`setupKey` is silently ignored — the prod token travels via the
`x-setup-token` header), and returns `{message, token, user}` — **no
totpSecret/QR is ever issued**. README corrected.

### 🔴 2. Security: plaintext password committed in seed script
`backend/prisma/seed.ts:12` hardcodes `bcrypt.hash('[redacted — was the hard-coded owner password]', 12)` —
a real password in git history. Editing the file is not enough (history keeps
it). Action: rotate the credential AND purge/replace history, or accept the
exposure for a paper-trading seed account. Flagged for owner decision —
not changed unilaterally.

### 🟡 3. `.env.example` cleaned (fixed 2026-10-14)
- **Added 35 keys the code reads but were undocumented** — headline:
  `POLYMARKET_PRIVATE_KEY` + `POLYMARKET_WALLET_ADDRESS` (required for any
  Polymarket trading), all five `CCXT_*` vars, `DISCORD/SLACK_WEBHOOK_URL`,
  `POLYGON_RPC_URL`, `SEC_CONTACT_EMAIL`, LLM cost-control vars.
- **Pruned 20 dead keys** with zero references in `src/`: AWS ×4, Supabase ×3,
  Twilio ×3, Coinbase ×2, `REDIS_URL`, `SENTRY_DSN`, `STOP_LOSS_*`,
  `TAKE_PROFIT_PCT`, `POLYMARKET_ALLOW_HEURISTIC_BETS`,
  `POLYMARKET_US_MAX_ORDER_USD`, `OWNER_PHONE`.

### 🟡 4. Redis is fake; Bull is dead; Twilio is dead
- `src/utils/redis.ts` is an **in-memory `Map` mock** ("data lost on container
  sleep"). `ioredis` is never imported; **`bull` is never imported anywhere** —
  the README's "Bull queue scheduler (analysis every 60s)" was false (the
  scheduler is `node-cron`). The `redis:7-alpine` container and `REDIS_URL`
  serve nothing. Decision needed: wire real Redis or delete
  `bull`/`ioredis`/`REDIS_URL` and any cross-instance state assumptions.
- `twilio` package + keys exist, but **zero code references** — alerts go
  through Discord/Slack webhooks only (`alertService.ts`). Remove or implement.
- CCXT is half-wired: package present, connector exists, but the 5 `CCXT_*`
  vars were undocumented until today (now added, §3).
